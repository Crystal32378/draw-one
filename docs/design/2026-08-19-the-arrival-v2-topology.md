# The Arrival v2 — 埕與沿革：無主神之廟的 topology

**作者：** 飛寶（Claude Fable 5）
**日期：** 2026-08-19
**性質：** 對三個新 constraint 的 topology 重推。修正 C 的一個核心假設。先不 code。
**前提不變：** 神無尊卑貴賤／空間可擴建／記得到訪不等於定義信仰。

---

## 0. 這一輪改了什麼

上一版的 C（常在的殿）有一個我沒有察覺的殘留假設：**「殿」是這座廟的基本單位**。
三個 constraint 一來，這個假設垮了——如果殿是基本單位，就永遠繞不開「哪間殿在中間」
「新殿排在哪」「系統送你進哪間殿」三個死結。

這一輪的修正：**廟的基本單位不是殿，是埕。** 殿是長在埕邊上的東西。

由此，五個問題全部有了不互相打架的答案。

---

## 1. Q1｜沒有固定主神，本廟的中心是什麼？——中心是埕

**中軸的終點不是任何一位神明的座，是一塊空地：埕。**

三個理由，由淺到深：

- **文化上有先例，而且就在中軸上。** 台灣廟宇的中庭本來就不是任何主祀神的位置——
  它是天公爐所在、是廟會發生的地方、是所有殿共同面向的空。合院建築的組織核心
  從來是中庭這個「空」，不是任何一間房。我們不需要發明「中心可以不是神」——
  傳統空間本來就這樣長。
- **產品上，中心本來就該是「問」。** Draw One 的核心價值是把心事寫成一句具體的問題。
  埕就是問題成形的地方：案在埕中，你的籤簿放在案上。整座廟環繞著「你來問」這件事
  組織起來——這不是妥協出來的中立，是產品真相的空間化。
- **信仰立場的空間化。** 「神無尊卑」最徹底的表達不是把三位排成一樣大，
  而是**讓中軸不供任何一位**。本廟的中軸供的是空——讓問題成形的地方。
  諸殿面埕而立，同一種姿態，無一在軸上。

一句話：**門 → 埕，軸到這裡就停了。從埕走向任何一殿，都是你自己轉的方向。**

## 2. Q2｜3 → 4 → 6 怎麼長？——沿革與埕殿文法（spatial grammar）

要設計的不是一張三殿平面圖，是**這座廟長新殿的文法**。兩條規則就夠：

### 文法一：殿必面埕（the courtyard rule）

每一位神明得到的位置，永遠是「**面向一個埕**」。這條規則同時是 anti-mall 測試的解：

> **走廊服務店面＝mall；殿面向埕＝廟。**
> Mall 的文法是「動線＋單元」（circulation serving units），
> 廟的文法是「共享的空＋面向它的殿」。
> 只要新神明得到的永遠是埕邊的一個面，這裡就永遠長不成購物中心，
> 月老也永遠不需要搭電梯。XD

### 文法二：位置依沿革（the chronicle rule）

殿的位置由**落成順序**決定——corpus 完成、通過 production gate 的真實日期。
這不是我們發明的排序：真實的廟本來就是這樣長的（龍山寺的後殿與偏殿都是
歷史增建的結果），而且**沿革是事實，不是價值判斷**。廟裡立一面「沿革記」，
如實寫：某年某月觀音殿、媽祖殿、關帝殿同期落成；某年某月增建月老殿。
訪客看得到這座廟的成長史——**擴建有紀念性，menu item 沒有**。

### 實際的成長模型

```
3 位（現在）   一進：山門 → 埕。三殿面埕（同期落成，環埕而立，無中軸位）。
4 位（月老）   埕的側面還有位：增建一殿面埕，沿革記上加一行、落款日期。
5–6 位        本埕滿（一埕至多四殿），開二進：過水廊 → 第二個埕，新殿面新埕。
```

- **深度不是位階**：二進的殿不是「更內更尊」，只是「更晚的篇章」——沿革記如實說明。
  每一進重複同一套文法（埕＋面埕之殿），所以走再深，語法都是廟，不會變成走廊。
- **導覽極限**：任何時刻，走到任何一殿＝沿軸前進＋至多轉一次。配置圖跟著建築長，
  永遠是唯一的全景視角（見 Q3）。
- **Stress test 過了**：第四位是增建、第六位是開新進——整座廟不用重畫，
  只有沿革記變長。

## 3. Q3｜空間如何有主次前後左右，而不被讀成神格高低？

關鍵發現：**provider 感的來源不是「等大」，是「同時並列可比較」。**
三張卡片的問題不在卡片一樣大，在於它們同時出現在同一視野裡等你挑。
真實廟宇裡諸殿明明有前後左右，卻沒有人讀出價目表——因為建築的不透明
讓你永遠一次只遇見一殿。

所以秩序與位階脫鉤的機制有四條：

1. **不同時**——殿以步行相遇，不以並列陳列。你永遠一次面對一位。
2. **同文法**——每一殿的儀式語法完全相同：同樣的案、同樣的籤筒、同一套紙
   （The Slip 已 freeze）、聖號同一種排版尺度。差異只在內容身分
   （聖號、籤系、沿革日期），永不在大小、裝飾、光。
3. **位置有據**——前後左右來自沿革（可查證的事實），且沿革記公開陳述：
   「本廟無主祀，諸神同尊，殿序依落成。」空間的秩序有解釋，位階的想像就無處著床。
4. **配置圖是地圖不是菜單**——配置圖的組織邏輯是空間相鄰（誰在誰旁邊、怎麼走到），
   不是選項比較（誰適合什麼問題）。地圖上絕不標「感情問月老」這類 routing 標籤——
   那一步踏出去，圖就變回型錄。

## 4. Q4｜初訪者的第一個位置在哪？——每個人、每一次，都到埕（C 的修正）

上一版說「回訪直接回到上次那間殿」。這一輪我把它修掉，理由是它在邊緣藏著
秘書問題：**自動把你放回某位神明面前，仍然是系統替你走了最後幾步。**

修正後的規則乾淨得多：

> **每一次打開，落點都是埕。初訪與回訪，同一個門，同一塊空地。**

- **初訪**：山門（規矩三行）→ 埕。案上是空的籤簿。四望，諸殿面埕——
  你在配置圖／埕上自己走向第一位。系統從頭到尾沒有指定任何方向。
- **回訪**：一個手勢內到埕。案上放著你的籤簿、未了的問題；牆上沿革記多了日期。
  「上次到訪：觀音殿・八月十七」作為**指路的事實**寫在往觀音殿的方向上——
  是路標，不是預設落點。想回去，你走；想見別位，你也走。
- **先在感不減反增**：precedence 的載體本來就不是「你被放在哪」，
  是**這座廟在你不在的時候繼續存在**——籤簿還在案上、沿革在變長、日期在走。
  埕作為固定落點反而讓「回來」的感覺更完整：你每次都從同一個地方回來。

副作用全是正的：問題成形（產品核心）天然發生在落點；一事一籤的呈現更空間化
——同一個問題再來，**案上就放著那張紙**；「走向神明」永遠是使用者當天的動作。

## 5. Q5｜「它記得你」記得什麼、絕不替你決定什麼

一條總原則先立住：

> **空間是公共的，記憶是私人的。**
> 廟的空間對每個人長得一模一樣——殿不因你的到訪頻率變大、變亮、變近。
> 你的痕跡只存在於你的物（籤簿、案上的紙）和事實性的路標上。
> Provider 會為你重新排列櫥窗；廟不會。

**記得（全部是事實，不是詮釋）：**

- 籤簿：抽過的籤、當時的問題、你的筆記、日期
- 一事一籤的綁定（同問題回到同一張紙）
- 上次到訪的殿與時間——顯示為路標事實，不作為落點、不作為排序
- 日期、節氣——廟自己的時間在走
- 沿革——廟自己的歷史（這是廟的記憶，不是你的）
- 使用者**明確做出的設定**（若未來提供，必須是使用者主動的動作，且可撤銷）

**絕不（每一條都是一種「替人定義信仰」的形式）：**

- 不統計「你拜誰最多」，不由此命名任何「常拜殿／主殿／你的神明」
- 不從問題內容推斷該去哪殿——**感情問題不會被自動導向月老**。
  問題→神明的 routing 是秘書問題的平方，未來任何功能都不得碰這條線
- 不推薦、不排序、不「你可能想拜」
- 不因人氣或到訪改變空間——任何殿不因數據變前、變大、變顯眼
- 不在配置圖上標註神明「專長領域」作為選擇引導

## 6. 五問一頁摘要

| 問 | 答 |
|---|---|
| 中心／中軸是什麼 | 埕。中軸止於空地，案與籤簿在埕中，諸殿面埕而立，無一在軸上 |
| 3→4→6 怎麼長 | 兩條文法：殿必面埕（anti-mall）＋位置依沿革（落成順序＝事實）。一埕滿四殿則開二進，語法遞迴 |
| 秩序≠位階 | 不同時（步行相遇）＋同文法（儀式語法全等）＋位置有據（沿革公示）＋配置圖是地圖不是菜單 |
| 初訪第一個位置 | 埕。每個人每一次都落在埕；走向任何一位永遠是使用者自己的最後幾步（C 的修正） |
| 記得／絕不 | 空間公共、記憶私人。記事實（籤簿、綁定、路標、沿革），絕不詮釋（無常拜殿、無問題 routing、無推薦、空間不因人而變） |
