# 入口 Ritual 決策備忘 — 天氣票怎麼進入產品

日期：2026-08-21｜作者：飛寶｜狀態：**等 Crystal 拍板，未施工**

V2C Sound（38ed950，frozen baseline）已把四張天氣票做完並全數通過味覺關，
但票目前只活在 `?weather=` dev flag。這份備忘把「票怎麼拿」的選項與代價攤開。

## 已定的約束（拍板過，不重議）

- 天氣改變地方，不改變神意（不進 draw／binding／interpretation；工程已鎖死）
- 一趟 visit 一張票，visit 內不換；埕內無 weather controls
- 可以不拿：不答＝常日（普通下午＝unmarked default）
- 不 preview：選擇在寂靜中做，世界過了門檻才開始（AudioContext 手勢啟動＝架構本身已保證）
- 文案不解釋：晴／陰／雨／風四個字，無 icon、無心情詞

## 結構性難題（上一輪辨識出的）

1. **山門是「初訪一次」**——「每次 visit 拿票」意味著回訪要重新出現一個門檻畫面，
   這推翻已 ship 的「boot 永遠落埕」。
2. **選單是被放逐的語法**——四個並排等你挑是這個產品的第一個 menu，且在主動線上。
   緩解：純文字、可跳過、（見選項 D）一天最多一次。

## 選項

### A. 薄門檻，每次回來都過
每次 visit 都有一息山門：日期節氣＋「天氣？」＋入內。初訪版另有三條規矩。
- ✚ 儀式最完整：門檻是每天的，不是第一天的
- ✚ 票語意最乾淨（一趟一張）
- ✘ 每日多次進出的人，每次都被攔一下——最重的摩擦
- ✘ 推翻「boot 落埕」最徹底

### B. 回訪不問，票長在埕內某處
- ✘ 直接違反「埕內無 weather controls」紅線。列出以示考慮過，**出局**。

### C. 不問——地方自己有天氣
節氣＋隨機（裝置時鐘先例＝void 刻字）決定今日天氣，零 UI。
- ✚ 最像「地方」：天氣發生在你身上，不是你設定的
- ✚ 零摩擦、零選單、不需要門檻回歸
- ✘ 失去整個「心裡下大雨」的主觀性——票的靈魂沒了
- ✘ 使用者永遠不知道為什麼今天有雨（可能是優點也可能是困惑）

### D. 一天一張票（推薦）
**「今天第一次來」才出現薄門檻**（日期節氣刻字＋天氣四字＋入內）；
同日再訪直接落埕，票沿用。跨日作廢，明天重新拿。
- ✚ 天氣本來就是「今天」的屬性——無鄰庵的票也是按日的；
  「一張屬於那天的票」在產品語意上完全兌現
- ✚ 摩擦封頂：一天最多被問一次，同日進出零成本
- ✚ 「boot 落埕」只在「今日已有票」時成立——修訂最小
- ✚ 儲存＝localStorage 帶日期戳（「上次到訪」LASTHALL 已有先例；
  存的是票不是 facing，不違反 boot neutrality——票是環境，朝向是位階）
- ✘ 需要一條新的持久化 key（arrival.ticket.v1：{date, weather}）
- ✘ 「同日第二趟心情變了」換不了票——接受：天氣一天一場，這是誠實不是缺陷

## 建議

**D，一天一張票。** UI 形態＝薄門檻一屏：上緣「八月二十一日・立秋」刻字、
中央「今天天氣？　晴　陰　雨　風」、下方「入內」。不選直接入內＝常日。
無 icon、無說明文字、選定後一息停頓再入內。初訪版維持三條規矩在前。

可延伸（不綁定本輪）：拿了票之後，void 刻字回聲成「八月二十一日・立秋・雨」——
地方把你的票寫進今天的石頭。

## 拍板需要的三個字

- 選 A／C／D（或再想）
- D 的話：不答＝常日，確認？
- void 刻字要不要回聲天氣（可後補）
